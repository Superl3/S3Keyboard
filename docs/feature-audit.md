# 기능 감사 및 1차 마무리 기준

기준일: 2026-07-12

이 문서는 자동 검증으로 증명된 범위와 실제 기기에서 추가 확인해야 할 범위를 구분한다. 단위 테스트 통과만으로 원격 앱 전달이나 손가락 사용감을 완료로 간주하지 않는다.

## 이번 감사에서 닫은 결함

- 빠른 설정에서 연속 입력을 켜거나 끌 때 `..`/Enter 행이 즉시 재구성되지 않던 문제를 수정했다.
- 연속 입력이 켜진 상태의 짧은 일반 탭이 약 500ms 지연되던 큐를 제거했다.
- 값이 없는 방향 슬라이드가 빈 입력으로 세션을 소비하지 않게 했다.
- 설정에서 `..` Enter 옵션과 연속 입력의 자동 복원 관계를 설명한다.
- `minSdk 23`에서 `java.util.function` 사용이 런타임 위험이던 구성을 core-library desugaring으로 수정했다.
- Android 12 이전/이후 모두에서 키보드의 로컬 설정과 입력 로그가 백업/기기 이전 대상이 되지 않게 했다.
- `check.ps1`에 Android lint를 포함해 API, 리소스, 접근성 오류를 표준 gate에서 차단한다.
- 긴 설정 화면을 단계, 검색, 접이식 하위 묶음으로 나눠 원하는 기능을 찾기 위해 전체 화면을 스크롤해야 하던 문제를 줄였다.
- 실제 입력 판정에는 사용되지만 화면에서 조절할 수 없던 키 밖 터치 허용 범위를 `터치와 슬라이드` 설정에 연결했다.
- 원격 설정은 기본 입력, 앱 자동 전환, 고급 앱별 예외로 분리해 처음부터 패키지 목록 입력칸이 모두 노출되지 않게 했다.
- 한 손가락 연속 입력의 다음 키 선택 원에 진입/이탈 히스테리시스를 적용해 경계의 작은 손떨림이 dwell 타이머를 반복 취소하지 않게 했다.
- 연속 입력의 원래 터치 키가 세션 내내 눌린 상태로 남던 표현을 제거하고, 후보 선택과 탭 확정 시간을 얇은 원형 진행 표시로 구분했다.
- 테마 선택 카드는 전환 버튼 없이 QWERTY와 Dingul 미리보기를 함께 보여주며, 외부 JSON 폴더 관리는 접힌 보조 영역으로 이동했다.
- 테마 편집기의 높이 메타 문구와 중첩 카드를 제거하고 `색상/형태/아이콘/글꼴`을 한 전역 카드 안의 하위 아코디언으로 정리했다.
- 한/영, 한손 배치, 입력 필드 surface처럼 키 행 모델이 바뀌면 진행 중 제스처를 즉시 종료해 이전 키 참조가 다음 배열에 남지 않게 했다.
- 옵션 키의 위 슬라이드/길게 누르기로 빠른 설정을 열 때도 현재 연속 입력 세션을 종료해 패널 뒤 입력을 차단한다.
- 로컬 데이터 화면의 라벨만 바뀌던 모형 연습 패널을 제거하고, 실제 IME 입력 필드에서 네 모음 키와 특수열까지 검증하는 연습 과정으로 통합했다.
- 빠른 시작 화면에서 사용자에게 보이지 않는 외형 편집 View를 생성하던 경로를 제거해 설정 진입 비용을 줄였다.
- 일반 입력의 기존 방향 fallback은 유지하면서 연속 입력은 실제로 매핑된 방향만 확정하도록 분리해, 빈 방향이 탭·삭제로 바뀌는 문제를 막았다.
- 빠른 시작에 한글/영문 배열, 사용 손, 연속 입력, 원격 모드의 현재 상태를 한 줄로 표시한다.
- 좌측 보조열의 음성 입력을 Android 표준 음성 인식 Activity에 연결하고, 같은 앱의 입력 연결이 복구된 뒤에만 결과를 커밋하도록 했다. 비밀번호·raw key·원격 필드에서는 시작하지 않는다.
- 설정의 검색과 단계 탐색은 화면 상단에 고정하고, 단계 내용만 스크롤되도록 분리했다. 단계 또는 검색 결과가 바뀌면 이전 단계의 스크롤 위치를 이어받지 않는다.
- `KeyboardSettings`의 모든 인스턴스 설정이 런타임 소비 지점을 갖는지 검사하는 `scripts/audit-settings-usage.ps1`을 추가하고 표준 `check.ps1` gate에 포함했다.
- 다음 키 중앙을 천천히 통과할 때도 선택 시간이 누적되던 연속 입력 경로에 안정 범위를 추가했다. 미세한 손떨림은 허용하지만 이동량이 범위를 넘으면 dwell이 마지막 안정 지점부터 다시 시작된다.
- 미등록 내부 명령 토큰은 일반 텍스트로 커밋하지 않고 `NOOP`으로 차단하며, 모든 `KeyboardCommands` 상수가 명시적 런타임 route를 갖는지 반사 기반 테스트로 검증한다.
- 실제로 항상 꺼져 있고 창 위치도 적용하지 않던 플로팅 키보드 scaffold와 숨은 preference를 제거했다. 클립보드 도구막대는 테마 대비색의 48dp 아이콘으로 바꿨다.
- 빠른 설정의 원격 전달 테스트와 테마·진단 도구를 기본 접힘 영역으로 이동하고, 저높이 설정 화면은 고정 헤더 대신 전체 스크롤로 전환한다.
- 클립보드 기록은 10개 항목뿐 아니라 항목당 4,096자 제한도 적용한다. 초과 텍스트는 잘라서 잘못 붙여넣지 않고 기록 대상에서 제외한다.
- 프리뷰 모션은 실제 출력에 영향을 주지 않던 lift, glow, squash, pressure 상태를 제거하고 작은 균일 scale-in과 release fade만 남겼다. 동시에 표시되는 프리뷰는 각자의 release clock을 유지하는 테스트로 검증한다.
- API 23의 `deleteSurroundingText` fallback은 코드포인트 수를 UTF-16 단위로 변환해 이모지의 절반만 삭제하지 않게 했다. 단어 삭제도 보조 평면 문자를 한 코드포인트로 계산한다.
- raw-key/Enter fallback은 key down/up 중 하나라도 편집기가 받았다면 동일 문자나 개행을 추가 커밋하지 않는다. 아무 키 이벤트도 전달되지 않았을 때만 텍스트 fallback을 사용한다.
- TalkBack 가상 키에 접근성 포커스 수명주기와 상·하·좌·우·길게 누르기 사용자 정의 작업을 추가해, 설명만 읽히고 탭밖에 실행할 수 없던 격차를 닫았다.
- 완료 텍스트 삭제는 선택 영역을 우선 지우고, 선택이 없으면 이모지 modifier·국기·ZWJ·결합 문자·분해형 한글을 하나의 grapheme으로 삭제한다.
- 설정 최상위 카드는 `+/-` 문자 대신 chevron과 접근성 상태를 사용하고, 접힘 상태에서 펼칠 때도 내부 간격을 동일하게 유지한다. 회전 후에는 선택 단계·전체 보기·검색어를 복원한다.
- 한/영 전환 연출은 화면을 가로지르는 강조색 sweep를 제거하고 짧은 저강도 wash와 하단 상태선 fade로 단순화했다.
- 연속 입력의 후보 선택·값 확정 타이머는 세대 토큰으로 구분해, 같은 키를 빠르게 다시 선택해도 이전 dwell 콜백이 뒤늦게 실행되지 않게 했다. 실제 Dingul 배열의 `만나서 반가워요` 시나리오가 동일 키 재진입과 스페이스를 포함해 상태 머신을 통과한다.
- 연속 입력 화면은 토글·현재 상태·속도·연습을 먼저 보여주고 상세 상태 설명은 접힌 `동작 방법`으로 이동했다.
- 빠른 시작에 Android 키보드 `활성화/전환`을 추가하고 빌드 정보는 Android/IME 단계로 이동했다. 빠른 설정은 일반 기능을 Remote보다 먼저 배치하고 화면 높이를 넘으면 내부 스크롤한다.
- 테마 선택 카드와 정적 테마 이미지에 QWERTY/Dingul 방향 힌트를 실제 키 매핑으로 표시하고, 개별 레이아웃 설명 라벨과 Dingul에 강제로 붙던 숫자줄을 제거했다. Dots처럼 레전드 전체를 glyph로 바꾸는 테마는 힌트를 계속 숨긴다.
- 연속 입력에서 키 선택 뒤 hitbox 이탈만으로 선택을 취소하던 조건을 제거했다. 좁은 우측 기능열도 방향 lock까지 원래 키를 유지하며, 실제 값이 없는 방향과 `NOOP`은 입력을 소비하지 않고 자유 이동으로 돌아간다.
- 빠른 시작은 Android의 활성 IME 목록과 현재 기본 IME를 읽어 `활성화 필요`, `전환 필요`, `사용 중` 상태를 안내하고 다음에 필요한 버튼만 강조한다.
- 원격·URL·비밀번호 앱 프로필에서 임시 적용된 언어/Remote/강제 숫자줄 상태가 빠른 테마 적용, 클립보드 테마 import, Remote/숫자줄 토글을 통해 전역 설정으로 저장되지 않도록 persisted/runtime 설정 경계를 분리했다.
- 클립보드 패널은 툴바 숨김뿐 아니라 실제 toggle 진입점에서도 기록 비활성화와 비밀번호 필드를 다시 검사한다.
- 좌측 보조열의 클립보드는 기록 꺼짐·보안 입력란·패널 미생성 상태를 구분해 안내하고, 항목을 붙여넣기 전에 현재 한글 조합을 확정한다. 시스템 Undo를 지원하지 않는 편집기도 무반응으로 끝내지 않고 안내한다.
- 연속 입력에서 후속 키를 빠르게 밀어 `ACTION_UP`에서 처음 방향 임계값을 넘는 경우도 입력을 확정하며, 연습 화면은 각 목표의 실제 키·방향 시퀀스를 함께 표시한다.
- 연속 입력의 중앙 선택 영역은 키캡의 꾸미기용 시각 간격이 아니라 안정된 터치 폭과 높이에 각각 비례하는 타원을 사용한다. 넓은 스페이스·하단 키의 가로 선택 영역을 확보하면서 세로 오선택은 늘리지 않고, 설정 상단에는 실제 반복 흐름인 `첫 키 → 확정 → 이동 → 다음 키 → 확정` 가이드를 표시한다.
- 레이아웃 여백·간격 조절기는 1dp 단위의 고정 크기 아이콘 버튼으로 통일하고, 현재 값이 포함된 TalkBack 설명과 범위 끝 비활성 상태를 제공한다.
- 설정 검색은 수동 단계 키워드뿐 아니라 실제 옵션 라벨·버튼·힌트를 인덱싱하며, 공백이나 구분자로 나눈 여러 검색어를 모두 만족하는 단계를 찾는다.
- 조합을 지원하지 않는 필드의 fallback 편집기는 자체 삭제·커밋의 예상 커서 이동량을 큐로 추적해 개별/병합 콜백을 구분하고, 선택 범위나 예상 밖 커서 이동은 외부 편집으로 즉시 수용한다.
- 선택 영역이 있을 때는 한글 이전 글자 자동 결합과 QWERTY 추천·자동교정을 중단해, 선택 텍스트만 일반 `commitText` 규칙으로 교체한다.
- 정적 테마 렌더러는 안전 파일명이 충돌하면 실패하고, 현재 카탈로그에 없는 이전 PNG를 제거해 테마 목록과 개별 QWERTY/Dingul 프리뷰 수를 일치시킨다.
- 빠른 설정과 설정 마법사의 선택 버튼은 Android `selected` 상태를 노출하고 최소 높이를 48dp로 통일한다. 원격 호환성 단축키는 최대 4열·두 줄 라벨로 배치해 5열 38dp 버튼의 터치 및 잘림 위험을 제거한다.
- Remote mode는 Ctrl+Win+Alt+Shift 전체 조합의 down/up 역순 해제, one-shot 소비, lock 유지, IME 단축키 전 modifier 초기화를 이벤트 시퀀스 테스트로 검증한다.
- 빠른 시작은 IME 비활성 상태에서 전환 버튼을 막고, 활성화 뒤에는 키보드 관리/전환의 다음 행동을 구분한다. 테마 선택기와 빠른 패널은 실제 현재 설정을 첫 항목으로 표시하며, 기본 모양 복원은 레이아웃·입력감이 유지됨을 확인한 뒤 실행한다.
- 키보드 높이, 입력 힌트·프리뷰와 사용자 글꼴을 바꿀 때 선택된 테마 ID가 사라지던 경계를 분리했다. 키 사이 시각 간격처럼 실제 테마 모양을 바꾸는 설정만 현재 테마를 사용자 설정으로 전환한다.
- 시각 역할 편집에서 테마 기본 배치나 컬러풀 테마 잠금이 활성화되면 스페이스·물음표뿐 아니라 숫자줄 색상도 함께 비활성화한다. 숫자 나열과 `override`, `visual`, `raw key` 같은 구현 용어는 실제 키 위치와 사용자 동작을 설명하는 한글 표현으로 바꿨다.
- 화면에 붙지 않은 색상·형태·숫자줄 컨트롤만 생성하던 `AppearanceSettingsController`를 제거했다. 테마 외형은 테마 편집기, 키 역할과 숫자줄 색상은 시각 역할 편집기가 각각 소유한다.
- 사용자가 아이콘 팩이나 키 표시 팩을 직접 바꾸면 포인트 키캡과 마찬가지로 선택 프리셋을 `현재 설정`으로 전환한다. 프리셋 이름은 유지되면서 실제 키 모양만 달라지던 상태를 없앴다.

## 실기기 확인 필요

- 실제 손 크기와 이동 속도에서 안정형/균형형/빠른형 dwell 시간이 자연스러운지 비교한다.
- 한 손가락을 떼지 않고 모음, 같은 키 재입력, space, delete, enter를 포함한 문장을 3분 이상 입력한다.
- Chrome, WebView, 메시지, 메모, 비밀번호 관리자에서 composing/selection/delete underline 회귀를 확인한다.
- TalkBack으로 키 탐색, 탭, 방향 힌트, 설정 화면 읽기 순서를 확인한다.
- Parsec, Moonlight, RDP에서 Android가 보낸 Esc/Tab/F-key/modifier/IME shortcut이 Windows까지 전달되는지 확인한다.
- 화면 회전, 낮은 높이, 큰 화면, 한손 모드, 숫자줄 조합을 실기기에서 확인한다.

## 1차 마무리 판정

코드와 자동 검증 기준으로는 closed beta 후보 빌드가 가능하다. 다만 위 실기기 항목 중 한 손가락 연속 입력 장시간 사용, 일반 앱 composing/delete, 실제 원격 수신 세 항목은 자동 테스트로 대체할 수 없다. 이 세 항목이 통과되기 전에는 전체 기능 완료로 판정하지 않는다.
