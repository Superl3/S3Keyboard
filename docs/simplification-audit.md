# Simplification Audit

This audit tracks evidence-based simplification targets for the keyboard codebase. The goal is to keep the current UX behavior while reducing duplicated paths, unused scaffolding, and regression risk.

## Current Evidence

- `HangulKeyboardView` is the largest class and owns rendering, gesture resolution, preview bubbles, touch learning capture, accessibility, and debug overlay state. This should be split by behavior only after characterization tests exist for each extracted path.
- `KeyboardSettings` and `KeyboardPreferences` carry most user and theme settings directly. New options should be grouped by an existing settings section or moved into focused value objects instead of adding more parallel scalar fields.
- `MainActivity` mixes settings hub layout, category construction, preview setup, demo handling, and data reset actions. UI simplification should extract section builders without changing saved preference keys.
- `S3KeyboardService` owns IME lifecycle, editor policy, Hangul composition, English assistance, remote mode, clipboard, quick settings, and command dispatch. Input correctness fixes should keep `InputConnectionTextOperator` as the only direct composing/commit/delete boundary.
- `RecentInputCorrectionController` was unused and has been removed. Geometry-only correction is already available through `TouchBiasStore`, so keeping an extra controller added API surface without behavior.
- Repeated Hangul automata committed-fragment calls in `S3KeyboardService` now route through one helper, keeping the composing replacement contract in one local place.
- Preview bubble width, position, lift, and corner-radius rules now live in `PreviewBubbleLayout`, so popup tuning can be tested without touching the full keyboard view.
- `PreviewBubbleLayout.liftPx(...)` now names its rise and hold curve boundaries instead of carrying raw timing fractions inside the branch conditions. The lift curve is unchanged, but future popup motion tuning has one explicit place to review.
- Released preview-bubble dedupe also uses `PreviewBubbleLayout.nearAnchor(...)`; `HangulKeyboardView` no longer owns the key-relative distance math for deciding which old popup should fade when a new key starts.
- Preview bubble animation no longer stores unused sequence or anchor-bottom state and samples one timestamp per rendered spec, reducing stale/torn popup motion without changing the overlay transport.
- Preview bubble rendering now samples one frame timestamp in `HangulKeyboardView.updatePreviewBubbles()` and passes it through pruning, active bubble updates, and spec construction. Multi-bubble popup motion no longer mixes several `SystemClock` reads inside one overlay update.
- Popup "input feel" is concentrated in `PreviewBubbleAnimation`: press pop, release commit impulse, fade timing, and release float are model-level values rather than duplicated `PopupWindow` state.
- `PreviewBubbleAnimation` now names the internal timing boundaries for press squash, release impulse, commit glow, release float, and confirmation pulse. Popup feel tuning keeps the same behavior but no longer depends on unlabeled fractional literals inside each animation query.
- Preview bubble active-state opacity is intentionally static; tactile feedback now comes from scale, squash, lift, and glow, avoiding a redundant alpha animation axis during rapid typing.
- `PreviewBubbleAnimation` now routes all elapsed-time animation ratios through one progress helper, so duration scaling, clamping, and timing math cannot drift between pop, motion, fade, release, supersede, and text-pulse effects.
- `PreviewBubbleAnimation` now handles motion-disabled exits at the public animation query boundary. Internal progress helpers assume motion is enabled and no longer pass repeated literal `true` flags through the timing math.
- `PreviewBubbleAnimation` now also keeps the shared bubble scale calculation behind `baseScale(...)`. `scaleX(...)` and `scaleY(...)` no longer call the public `scale(...)` method with a hard-coded motion-enabled flag just to reuse the same math.
- `PreviewOverlaySpec` now carries only the scale axes that `PreviewOverlayController` applies. The old single `scale` pass-through is intentionally removed so popup motion has one rendered representation.
- `PreviewOverlayController.applySpec(...)` now delegates text styling, transform/elevation, typeface, and background creation to focused helpers. The `PopupWindow` transport still owns pooling and placement, but the visual application path no longer mixes every spec concern in one method.
- `PreviewOverlayController` no longer assigns a redundant default typeface when pooled overlay labels are created. Popup text styling now has one owner: `applyTypeface(...)` through `KeyboardTypefaceCatalog`.
- `PreviewOverlayController` now creates pooled overlay labels hidden and only marks them visible when a concrete `PreviewOverlaySpec` is applied. This keeps popup view reuse explicit and avoids stale pooled views becoming visible between rapid key previews.
- `PreviewOverlayController.show(...)` now delegates top padding, bottom bounds, spec application, unused overlay hiding, and popup show/update steps to focused helpers. The native `PopupWindow` transport stays intact, while popup placement no longer mixes measurement and child-view mutation in one block.
- Keyboard rendering color math is shared through `KeyboardColorMath`. `HangulKeyboardView`, `KeyboardDebugOverlayRenderer`, `PreviewOverlayController`, `PreviewBubbleDrawable`, `ClipboardPanelController`, and `ThemeEditorActivity` no longer carry separate alpha/luminance/contrast implementations, and the popup drawable caches background luminance for highlight, shadow, tail, and lip passes.
- `PreviewBubbleDrawable` now also routes body highlight, shadow, and lower-lip two-stop effects through one adaptive gradient helper. The popup effect stack stays visually the same, but luminance-aware two-stop alpha selection is no longer repeated in each draw method.
- `HangulKeyboardView` now passes `emitValue(...)` to `RepeatController` as a standard `Consumer<String>` method reference. The repeat-to-emit path stays the same without a controller-specific one-method callback interface.

## Current Input Fix Notes

- URL, email, web-edit, and WebView text profiles keep Hangul composing enabled while still preferring ASCII and disabling risky text conveniences. Browser/search fields should not fall back to commit-only jamo input when the user explicitly toggles to Hangul.
- Preview popup tuning now follows platform keyboard preview behavior more closely: the popup is a compact rounded magnified keycap with a tiny scale-in and short release fade. Runtime preview no longer uses angular tail drawing, float/lift motion, release pulses, or glow-heavy effects.

## Preferred Direction

- Keep the native `InputMethodService` implementation. It is the correct Android integration point and avoids framework mismatch for IME lifecycle, `EditorInfo`, and `InputConnection`.
- Keep preview popups on the existing `PopupWindow` overlay path. The bloat risk is not the native primitive, but duplicated animation/rendering state. Prefer one small animation model plus one drawable.
- Keep Hangul composition inside `HangulAutomata` plus `InputConnectionTextOperator`. Avoid committing text directly from service branches because composing behavior regresses easily across editors.
- Prefer existing deterministic gesture scoring over ML/swipe frameworks for Dingul input. The project target is small-grid Korean gesture input, not dictionary-driven full-word swipe typing.
- Treat debug, diagnostics, and practice panels as optional surfaces over existing state. They should not own input state or duplicate correction logic.
