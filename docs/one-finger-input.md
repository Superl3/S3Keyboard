# 한 손가락 연속 입력

한 손가락 연속 입력은 Dingul 배열에서 첫 터치 이후 손가락을 떼지 않고 문장을 이어 쓰는 선택 기능이다. 기본값은 꺼짐이며 QWERTY와 Remote mode에는 적용되지 않는다.

## 켜는 곳

1. 앱을 열고 `연속 입력` 단계를 선택한다.
2. `한 손가락 연속 입력 사용`을 켠다.
3. 처음에는 `균형형 · 추천`을 사용한다.
4. 입력이 자주 빠지면 `안정형`, 확정이 답답하면 `빠른형`을 선택한다.

현재 상태 요약에는 `중앙 선택` 시간과 `탭 확정` 시간이 표시된다. 방향 입력은
중앙 선택 뒤 밀기가 잠기는 즉시 확정되므로 두 시간을 합친 글자당 속도로 표시하지
않는다. 먼저 추천값으로 연습하고, 원치 않는 키가 선택될 때만 안정형으로 바꾸는
편이 안전하다.
상세 상태 설명은 같은 단계 하단의 접힌 `동작 방법`에서 확인할 수 있다.

설정 상단의 4단계 표시는 `첫 키 → 확정 → 이동 → 다음 키` 순서를 요약한다. 마지막
`다음 키`에서 두 번째 `확정`으로 돌아가는 화살표는 손가락을 뗄 때까지 두 단계를
반복한다는 뜻이다. `확정`은 중앙에서 계속 기다려 탭 값을 입력하거나, 상하좌우로
밀어 방향 값을 입력하는 두 방식을 모두 포함한다.

같은 화면의 `바로 연습`은 `어아오우`, `워와외위`, `으에애왜웨`, `요야유여`, `?.,/`, `만나서 반가워요`, `타각기 어때요` 순서다. 각 단계에서 목표 문장뿐 아니라 실제 키와 탭·방향 순서를 함께 보여준다. 네 모음 키의 모든 방향, 우측 특수열, 동일 키 재진입, 문장 입력을 차례로 확인한다. 일치한 글자는 강조되고 잘못된 위치는 즉시 표시되며, 연습 입력은 설정이나 로그에 저장하지 않는다.

키보드의 옵션 키를 탭해 여는 빠른 설정에서도 이 기능을 켜고 끌 수 있다.

## 입력 순서

1. 첫 키를 누른 채 잠깐 멈춘다. 해당 키의 탭 값이 입력되고 자유 이동 상태가 된다.
2. 손가락을 떼지 않고 다음 키 중앙으로 이동한다.
3. 짧게 멈추면 그 키가 선택된다. 이때 짧은 햅틱이 한 번 온다.
4. 선택한 채 기다리면 탭 값이 입력된다. 상하좌우로 밀면 해당 방향 값이 바로 입력된다.
5. 입력이 끝나면 다시 자유 이동 상태가 된다. 손가락을 떼면 세션이 종료된다.

자음 키에서 방향 입력을 확정한 직후 같은 키의 탭 값이 다시 필요하면, 손가락을
떼거나 키 밖으로 크게 우회할 필요 없이 같은 키 중앙으로 돌아와 한 번만 멈추면 된다.
이 경우에는 다음 키 선택과 탭 확정의 두 대기를 합쳐 한 번의 안정 대기만 사용한다.
자음의 연속 입력과 획 추가 흐름을 빠르게 하기 위한 예외이며, 모음 키나 단순 탭 뒤의
같은 키 반복에는 적용하지 않아 중복 입력 방지 동작을 유지한다.

키 중앙의 얇은 표시는 대기 시간을 보여준다. 아직 눌린 배경이 없는 키의 넓은 타원이 차는 동안은 `다음 키 선택 대기`, 눌린 배경 위의 작은 원이 차는 동안은 `탭 값 입력 대기`다. 상하좌우로 밀면 원이 끝날 때까지 기다리지 않고 해당 방향 값을 바로 입력한다.

`?`, `.`, `/`, 삭제처럼 폭이 좁은 우측 기능열 키는 방향을 아예 확정하지 않는다. 선택된 뒤 손가락이 hitbox를 벗어나 어느 방향으로 흔들리거나 밀려도 방향 입력으로 넘어가지 않고 원래 키가 선택된 상태로 남아 탭 값만 기다린다. 이 키들은 폭이 좁아 인접 키와 붙어 있어 슬라이드 도중 스치기만 해도 방향이 잘못 잠기기 쉬웠기 때문에, 항상 탭으로만 반응하도록 고정했다.

값이 확정되는 순간의 실제 손가락 위치가 다음 입력을 판단하는 기준점이 된다. 방향 슬라이딩으로 확정한 경우 이 기준점은 키 중심이 아니라 슬라이딩이 끝난 지점이며, 손가락이 그 지점에서 일정 거리 이상 벗어나야만 다음 키 후보 탐색이 시작된다. 이 규칙은 슬라이딩 직후 손가락이 원래 키 중심에서 멀어져 있는 상태에서도, 그리고 손가락의 미세한 흔들림에도 옆 키가 곧바로 잘못 선택되거나 중복 입력되는 것을 막는다.

다음 키가 선택되는 순간에는 직전 이동의 관성이 아직 남아 있을 수 있다. 손가락이 이미 다음 키 쪽으로 이동하던 중에 선택 대기 시간이 끝나면, 선택 직후에도 그 관성으로 인한 미세한 이동이 잠깐 이어진다. 이 관성이 우연히 다른 방향 값과 같은 방향으로 겹치면 원치 않는 방향 입력이 확정될 수 있으므로, 선택 직후 아주 짧은 동안은 방향 확정을 보류하고 그 이후의 이동만 방향 판단에 반영한다. 이 지연은 첫 키를 누르자마자 미는 동작에는 적용되지 않는다. 손가락이 막 화면에 닿은 시점이라 이어지는 관성이 없기 때문이다.

다음 키를 고르는 중앙 영역은 키의 안정된 터치 폭과 높이에 각각 비례하는 타원이다. 스페이스처럼 넓은 키는 가로 선택 영역도 함께 넓어지지만, 세로 영역까지 불필요하게 커지지는 않는다. 진입할 때보다 빠져나갈 때의 범위가 조금 더 넓어 중앙 경계에서 손가락이 작게 흔들려도 선택 대기 시간이 초기화되지 않는다. 반대로 아직 선택 진동이 오기 전에 중앙을 지나 이동 중이면 누적 이동량이 안정 범위를 넘을 때마다 선택 시간이 다시 시작되므로, 천천히 통과한 키가 의도치 않게 선택되지 않는다. 다른 키 쪽으로 분명하게 이동하면 후보만 해제되고 자유 이동을 계속한다.

테마의 키 사이 시각 간격을 바꿔 키캡 면이 작아져도 이 중앙 선택 범위는 키의 안정된
터치 영역을 기준으로 계산한다. 꾸미기 설정 때문에 연속 입력 난이도가 달라지지 않는다.

## 짧은 예시

`가`를 입력하는 흐름:

1. `ㄱ` 중앙에서 기다려 `ㄱ`을 확정한다.
2. `ㅣ.` 중앙으로 이동해 짧게 멈춘다.
3. 오른쪽으로 밀어 `ㅏ`를 입력한다.
4. 손가락을 떼어 입력을 끝낸다.

모음·특수열 연습과 문장 `만나서 반가워요 타각기 어때요`의 실제 키/방향 조합은 단위 테스트 `DingulOneFingerLayoutSequenceTest`에서 현재 배열과 함께 검증한다.

## 동작 원칙

- 첫 키를 짧게 탭하고 떼면 기존 Dingul 탭 입력처럼 즉시 전송되며 별도 대기 시간이 없다.
- 방향이 확정되기 전에는 문자를 보내지 않는다.
- 방향이 확정되면 해당 방향 값만 보내고 자유 이동 상태로 돌아간다.
- 빠르게 밀어 마지막 `ACTION_UP`에서 처음 임계값을 넘은 경우에도 선택된 키의 방향 값을 확정한다.
- 후속 키의 방향 기준점은 키 중앙이 아니라 사용자가 선택을 확정한 실제 손가락 위치다.
- 옵션 키를 직접 길게 누르는 빠른 설정 경로는 연속 입력보다 우선한다. 전체 앱 설정은 옵션 키를 탭해 연다.
- `..` 위치의 Enter 치환은 별도 레이아웃 옵션이며, 연속 입력이 켜지면 원래 모음/공백 키가 사용된다.
- 값이 없는 방향으로 잘못 밀면 빈 입력을 확정하지 않고 자유 이동 상태로 돌아간다.

## 개발자 검증

- 디버그 빌드의 `키 영역 표시`를 켜면 현재 flow 상태와 선택 키를 확인할 수 있다.
- `COMMITTED_FREE_ROAM`은 다음 키를 탐색하는 상태다.
- `CANDIDATE_HOVER`는 키 중심에서 선택 대기 중인 상태다.
- `KEY_SELECTED`는 방향 입력 또는 탭 확정을 기다리는 상태다.
- `ACTION_LOCKED`는 방향이 잠긴 직후의 상태다.
- 디버그 상단의 `pending=TARGET_SELECTION`은 다음 키 선택 대기, `pending=ACTION_COMMIT`은 탭 값 입력 대기이며 남은 시간이 ms로 표시된다.

에뮬레이터에서는 Android monkey raw pointer 시퀀스로 `ㄱ hold → ㅣ. center dwell → right slide`를 보내 `가`가 입력되는지 확인할 수 있다.
